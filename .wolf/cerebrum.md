## Key Learnings

- **Python exact-integer codegen has two safeguards mirrored across CLI and Web.** The expression builders emit direct `int(field) & mask` / raw signed expressions for `is_identity_integer`, so pusher `timestamp` bypasses conversion helpers. Both Python generators also emit `_is_identity(scale, offset)` guards inside all four runtime conversion helpers as defense-in-depth. Browser-generated pusher source is byte-identical to CLI output and the committed target artifact; an execution regression runs the generated Python and checks all four helpers plus `0xFEDCBA9876543210`. When embedding Python docstrings in TypeScript template literals, escape Markdown backticks as `\`` so they survive into generated source without terminating the template.
- **toc-climb-stairs pusher replacement boundary.** Browser-executed `parseMavlinkXml()` + Web `generatePython()` can replace only `src/toc_climb/protocols/generated/mavlink_pusher.py`: it emits CMD 460/47 bytes/CRC 57 and STATUS 461/63 bytes/CRC 8, omits fake bus metadata, and passes focused target tests when injected in memory. Retain `mavlink_transport.py` for MAVLink-v2 header/X25 CRC/29-bit ID/classic-CAN 8-byte fragmentation/reassembly and retain `motion/pusher.py`/`pusher_service.py` for control logic. The target codec initially predated exact-integer codegen and corrupted large `uint64 timestamp` values (`0xFEDCBA9876543210` became `0xFEDCBA9876543000`); it has since been regenerated and now round-trips exactly. Web and CLI pusher payload behavior matches, though a later CLI-only runtime-helper hardening makes their generated source text differ.
- **The toc-climb-stairs pusher subset is stale relative to robot `mavlink_bridge@ee6f24e8`.** Both linear-actuator message elements and four of five referenced enums match exactly, but local `LINEAR_ACTUATOR_ERROR` stops at 4 while robot/can-codec also define storage errors 5–8. Regenerate `configs/can/mavlink_pusher.xml` from the robot-identical can-codec `user_define.xml` before Web GenLib; payload layout/CRC are unchanged, but generated enum constants and human-readable error reporting otherwise remain incomplete.
- **Motor Controller V2 enable returns two `RegResponseByte` acknowledgments; it is not a normal enable-state readback.** Both use register `0x28`: `status`/Byte 1 = 0 carries execution result in Byte 2 (`00` success, `FF` already enabled, `FE` motor error, `FD` motor encoder uncalibrated, `FC` brake uncalibrated); `status`/Byte 1 = 1 carries brake-open result (`01` success, `00` failure). Thus `28 00 00` means success, not disabled. Position-PVT order is enable → validate both responses → `SwitchMode(POSITION_CONTROL, submode=1)` (`0x81` / `20 00 01 01`) → repeat `PositionControl` on `0x481` → disable.
- **All-joint PVT synchronization uses individual CAN frames grouped into one control cycle.** Enable nodes 1–7 one at a time with both acknowledgments validated, then switch all nodes to position mode. At each rate tick send `PositionControl` consecutively on `0x481..0x487`; this keeps joint commands within one short bus burst without relying on the generated concatenated-payload broadcast format. On partial enable failure, disable successfully addressed nodes in reverse order and never enter mode/PVT.
- **Motor V2 SocketCAN position snapshots and effort use different feedback paths.** `ReadReg(POSITION=35)` returns a six-byte `RegResponseFloat32` frame on `0x100 + node`, with Byte 1 status 0 required. Joint effort comes from the 12-bit big-endian torque field at bits 28–39 of the 7/8-byte `MotorStatusCompact`/`MotorStatus` command-feedback frame on `0x680 + node`; do not request `ReadReg(TORQUE=37)`. Decode node-specific ranges as nodes 1–2 ±40 N*m, nodes 3–4 ±70 N*m, and nodes 5–7 ±12 N*m. The SocketCAN hold workflow snapshots every selected position, validates each two-frame enable/brake handshake, switches position mode, streams each snapshot as that joint's PVT target, consumes the resulting command feedback, then disables in reverse order. With defaults `can0,can1` × nodes 1–7 this addresses 14 motors. Raw CAN-FD frames set `CANFD_BRS=0x01` so configured data bitrate is used.
- **Binding a raw SocketCAN socket does not prove the link is usable.** Linux can allow bind while the interface is DOWN; the first CAN-FD send then returns `ENETDOWN`, and follow-on sends may return `EINVAL`. Before opening motor sockets, require sysfs `flags & IFF_UP` and MTU 72 for CAN FD. The utility's `setup` / `--configure-interfaces` path runs `ip link set <if> down`, configures bitrate 1M, dbitrate 5M, `fd on`, `restart-ms 100`, then brings the link up. A bus-off/down send failure should be reported once per interface with that remedy, not once per motor.
- **SocketCAN all-motor enable must not serialize command and response waiting.** The first implementation sent one enable, blocked until both execution/brake responses arrived, then advanced to the next motor. Across 14 joints this unnecessarily serialized activation and exposed later nodes to timing failures. Send all selected enable writes in a fast batch, record an individual deadline immediately after each write, then use `select` across both interface sockets and demultiplex acknowledgments by `(interface, response CAN ID)`. Any explicit failure or missing response still reverse-disables every commanded target.
- **Motor V2 enable/disable and brake lock/unlock are different registers.** `ENABLE_STATE` is register `0x28`: value 1 enables and value 0 disables, with the special two-response enable handshake. Physical brake control is `SWITCH_BREAKER` register `0x47`: `{47 00 01}` releases/unlocks and `{47 00 00}` locks. The local product-tool protocol independently confirms `state=1 release, state=0 lock`.
- **PVT hold and command-feedback effort share one nonblocking SocketCAN event loop.** Never call the standalone `read_current_joint_efforts()` collector from inside hold because it waits for a full selected-joint snapshot. Keep PVT deadlines primary, use `select` across both interfaces, passively consume `MotorStatus`/`MotorStatusCompact` frames on `0x680 + node`, retain the latest torque per `(interface, node)`, and print compact snapshots at the separately configurable display rate (default 5 Hz). Missing feedback displays `--` while PVT continues, but any nonzero Byte-5 `error_code` must terminate hold immediately and flow through reverse-disable cleanup. Hold runs indefinitely unless Ctrl+C, a feedback error, or an explicitly supplied duration stops it; it must never send `ReadReg(TORQUE=37)`.
- **Generated Python `decode_frame()` is currently first-match only and does not disambiguate same-ID RX variants by payload length.** Motor Controller V2 has `MotorStatus`/`MotorStatusCompact` on the same node ID with 8/7-byte payloads and six `RegResponse*` layouts on `0x100 + node`. External read-only monitors must filter `ALL_MESSAGES` to RX classes and require exact `PAYLOAD_BYTES == len(data)` before decoding, or compact/byte responses will be padded and misdecoded as the first class.
- **Web GenLib controller support is emitted as a companion starter, never folded into the protocol codec.** `web/src/lib/codegen/controller.ts` generates an editable transport entry point that imports/includes the zero-dependency codec, so a hardware-specific controller can be regenerated or replaced without forking generated message code. Current profiles lock the codec language where necessary: Linux SocketCAN (Python/C99), USB SLCAN-FD via python-can + pyserial (Python 3), STM32Cube HAL FDCAN (C99), and ESP-IDF TWAI (C99). SLCAN-FD uses `interface='slcan'`, a serial channel (default `/dev/ttyACM0`), and `bus.set_bitrate(nominal, data)`; upstream python-can currently supports 2M/5M data rates. TWAI must be unavailable for CAN FD or payloads over 8 bytes; controller starters must be disabled for MAVLink configs because they need a separate transport framing/system-ID layer.
- **A source-only fix to a `.svelte.ts` singleton runes store (e.g. `plotStore`) is NOT live until the runtime reloads it.** Vite HMR does not reliably hot-swap methods on an already-instantiated exported singleton — the running page keeps the old instance/method. After such a fix you MUST fully restart `vite dev` AND hard-reload the browser (Cmd+Shift+R); the deployed Cloudflare site needs `npm run deploy` (build + wrangler pages deploy). Verifying via committed source / a node unit-test alone is insufficient — confirm the *running* app reloaded. (bug-169: the formula phantom-spike fix was correct but the user kept seeing the old behavior because a long-running dev server + un-redeployed site were still executing pre-fix code; proven by reproducing the exported CSV's delta column byte-for-byte with the OLD merge.)
- **Plot formula multi-var merge (`_computeSamples` in plot-store.svelte.ts) must coalesce same-timestamp events.** Signals co-sampled in one frame share an identical timestamp. A per-event sample-and-hold loop that evaluates after each event produces a phantom sample `a(tᵢ) − b(tᵢ₋₁)` (fresh a, stale b) plus a duplicate emit per timestamp. The merge groups all events at the same `time` and evaluates once. - **Same-ID multi-node disambiguation is a 3-stage funnel: ID range → DLC → `constant: true` signals.** `_find_message_by_id` / `findMessageById` take the frame bytes too; after DLC narrowing, any candidate whose `constant: true` signals don't match the actual bits is rejected, then the candidate with the most matched constants wins. - **MAVLink XML `<extensions/>` marker:** Per the MAVLink2 spec, fields after `<extensions/>` are appended to the wire payload in *declaration order* (NOT sorted by size) and are *excluded from CRC_EXTRA*. Only core fields (before the marker) are size-sorted and contribute to CRC_EXTRA. This must be done by walking the message's child elements in order — `querySelectorAll('field')` / `findall('field')` won't tell you which side of the marker each field is on. Implemented in `canfd_codec/mavlink_loader.py` `_parse_messages` and `web/src/lib/config-loader.ts` `parseMavlinkXml`.
- **MAVLink-over-CAN multi-frame reassembly:** Continuation CAN frames carry no identifier (only the first frame has 0xFD). This handles realistic interleaving at *different* CAN IDs cleanly; at the *same* CAN ID with same-size messages, FIFO can mis-assign continuation frames — limitation by design since continuation frames have no ID. The reassembler is used by `canfd_codec/monitor.py`, `cli.py cmd_decode` (multi-data args), and `web/src/lib/plot-store.svelte.ts` analyze+handleLiveFrame.

- **`every` statement semantics — TWO modes triggered by `durationMs`.** When `durationMs` is unset, `every` is *background*: parent body advances immediately, the periodic task keeps firing until the *enclosing body* ends (the `_runBody` finally clears intervals it tracked) or `stop()` is called. When `durationMs` is set, `every` is *blocking*: parent waits for the duration, then the interval is cleared. Tests rely on this: heartbeat + commands needs background; "burst for N ms then continue" needs bounded. Each `_runBody` invocation tracks its own `localIntervals` so background `every`s scoped inside `repeat`/`group` get cleaned up at scope end — don't leak intervals up to the top scope.
- **Discriminated-union AST mutation pattern.** `SeqStatement` is a union; methods like `addStmt(parent, stmt: Omit<SeqStatement,'id'>)` cause TypeScript to lose per-variant property access (e.g. `raw` on `SendStmt`, `body` on `RepeatStmt`). Fix: make the method generic: `addStmt<T extends SeqStatement>(parent, stmt: Omit<T,'id'> & {id?: string})`. Callers can pass plain literals when T can be inferred, or write `addStmt<SendStmt>(null, {...})` for explicit narrowing. Inside the method, cast as `unknown as SeqStatement` (not just `as SeqStatement`) — when the union has variants with required fields not present on the generic (e.g. `SetStmt.name`, `SetStmt.expr`), TS rejects the single-step cast. The mutateAst() helper uses `JSON.parse(JSON.stringify(ast))` for deep clone — fine for AST values which are POJO-shaped (no functions/Dates), and forces full Svelte 5 reactivity by reassigning the top-level array.
- **Sequence variables = `set` statement + `=expr` syntax + tiny arithmetic evaluator.** `SetStmt { type:'set', name, expr }` writes to a per-run `vars: Record<string, number>` map (cleared on `start()`). Any send value of the form `"=expr"` is resolved against `vars` at send time. The evaluator is a hand-written recursive-descent parser supporting `+ - * / %`, parentheses, unary `+/-`, decimal and hex literals (`0x10`), and bare identifier lookups. NOT `eval()` and NOT Turing-complete — just arithmetic. Throws on undefined variable, malformed input, or trailing tokens. For the preview path (`encodeSendPreview`), the store walks the AST in document order up to the target send and replays any `set` statements it encounters — best-effort: skips disabled, ignores per-iteration updates in repeat/every (one pass through bodies). Variables only resolve numerically; for fields that take other shapes (bitfield bitmaps, enum-name strings), the user keeps writing literal values as before.
- **HTML5 drag-and-drop on tree rows.** Five rules that prevent the common pitfalls: (1) put `draggable=true` on the row itself for "click-anywhere to drag" UX, then in `dragstart` call `e.preventDefault()` if `e.target.closest('input, select, textarea, button, label, .ast-actions, .send-editor')` — this keeps form controls / nested editors interactive while making the row body grab-able. (2) **CRITICAL when rows nest:** call `e.stopPropagation()` in `dragstart` and `dragend`. Without it, the inner row's `dragstart` bubbles to the parent's draggable row, which fires its own handler and overwrites `dragId` to the parent's id — so dragging a child out of an `every`/`repeat`/`group` silently moves the *container* instead of the child. (3) In `dragover`, MUST call `e.preventDefault()` to signal "drop allowed here" — otherwise `drop` won't fire — and `e.stopPropagation()` so only the innermost row resolves the drop target. (4) **Anchor before/after/inside drop zones to the row's HEADER element (`.ast-line`), NOT the whole `.ast-row` bounding rect.** When a container has children, its row can be hundreds of pixels tall, and using the full rect makes the middle 40 % "inside" zone swallow the entire body — leaving no usable drop area for children-of-the-container to be dragged *out*. With the header as anchor: cursor above bottom of header is before/after based on top/bottom half; cursor below the header is 'inside' (for containers) or 'after' (for leaves). (5) Cycle check direction matters: refuse drops where the *target* lives inside the *dragged subtree* — i.e., walk dragId's body looking for stmt.id, not the other way around. The opposite direction (walking stmt.body for dragId) is "already inside" check, which is a different concern (and dropping inside a container you're already in is a valid reorder-to-last move, not a refusal case). Don't try to use `dragleave` to clear the drop indicator — it fires unpredictably when moving between child rows. Just let the next `dragover` overwrite it, and clear on `dragend`.
- **Drag-and-drop cycle prevention.** When the user drags a container into one of its own descendants, the move must be refused — otherwise the tree becomes a cycle and recursive traversal hangs. Implement as `_isDescendantOf(maybeChild, maybeAncestor)` walking the ancestor's body subtree. Cheap because the AST is small. Sequence-store's `moveStmtTo` does this check before mutating; the UI also short-circuits `dragover` (no `e.preventDefault()`) so the cursor shows a "no drop" icon and the drop indicator never appears.

## Do-Not-Repeat

- [2026-08-05] **Do not infer that a generated runtime helper is used by a field merely because the helper remains in the output.** Inspect the emitted per-field expression: current identity integers bypass `_p2r_*`/`_r2p_*` entirely. Also do not harden only the CLI Python runtime helper while claiming Web parity; mirror production-generator changes in `web/src/lib/codegen/python.ts` and verify browser-generated source.
- [2026-07-30] **Do not interpret Motor Controller V2's first enable response `28 00 00` as enable state 0.** It is execution result 0 = success. Wait for and validate both enable acknowledgments (`status=0` execution and `status=1` brake), then switch mode and stream PVT. Also do not reverse enable/mode order or send PVT only once.
- [2026-07-30] **Do not retain a typed confirmation prompt or silently limit the requested all-joint test to node 1.** `--enable-and-zero` is the explicit opt-in; default active nodes are 1–7, with `--nodes` available for a subset. PVT frames for all selected nodes belong in every timing cycle.
- [2026-07-30] **Do not reuse a one-frame generated SocketCAN starter for multi-joint stateful control.** It lacks receive parsing, multi-interface ownership, enable acknowledgments, per-joint snapshots, and rollback. Keep the generated codec untouched; expand the editable companion with explicit resource cleanup and reverse-order disabling.
- [2026-07-31] **Do not start per-motor writes merely because SocketCAN bind succeeded.** Preflight every selected interface for IFF_UP and the correct CAN/CAN-FD MTU first; otherwise one link-level condition becomes a noisy list of 7 or 14 motor failures. Keep interface configuration opt-in because taking a live CAN link down/up can disrupt other users.
- [2026-07-31] **Do not block for each Motor V2 brake acknowledgment before sending the next enable.** Batch all selected enable writes first, then collect out-of-order responses concurrently with per-motor deadlines; otherwise activation is needlessly serialized across 14 joints.
- [2026-07-31] **Do not call register 0x28 lock/unlock.** It is enable/disable. Reserve lock/unlock for `SWITCH_BREAKER=0x47`, with value 1 releasing the brake and value 0 locking it.
- [2026-07-31] **Do not read Motor V2 effort from register 37 inside or outside a PVT hold loop.** Effort is the torque field in `MotorStatus`/`MotorStatusCompact` command feedback on `0x680 + node`. Collect those frames opportunistically between PVT deadlines; missing feedback must not pause or terminate position holding.
- [2026-08-01] **Do not silently stop SocketCAN hold after a default duration or ignore command-feedback error flags.** Default duration is unbounded. Decode Byte 5 of both MotorStatus DLC variants, abort on every nonzero value with its named flags, and let `finally` reverse-disable all enabled targets for both feedback errors and Ctrl+C.
- [2026-08-01] **Do not leave the SocketCAN hold default at 1 A when the established conservative ceiling is 3 A.** `PositionControl.max_current` is the runtime current/torque limit; default it to 3 A, expose that value in startup output and CLI help, and continue rejecting values above 3 A.
- [2026-07-20] **Do not stack a tiny creator backlink beneath a product name in a compact tool header.** The user found the two-line `CAN Codec` / `More by Lue` lockup ugly. Keep product and creator credit on one baseline with a subtle divider; reserve the longer localized wording for the tooltip and accessible label.
- [2026-05-06] When renaming a field in a persisted type (e.g. localStorage), always add migration/normalization logic that handles old stored data. An entry may exist with the old field name, causing undefined access on the new name. Use a normalizer that ensures all required fields exist.
- [2026-05-06] In Svelte 5, never mutate `$state` objects inside template expressions or `$derived`. Methods called from templates (like `getMessageFilter`) must be pure reads — return new objects with safe defaults instead of mutating the source. Mutations are only safe in event handlers (onclick etc.).
- [2026-05-16] **When sharing a connection across pages (busStore), connection state and per-consumer subscriptions are separate concerns — don't conflate them.** Bug-057: plot only subscribed its frame callback inside `connectLive()` (the Connect button handler). When /encode connected the bus first, plot's Connect button was hidden and the callback never subscribed — frames flowed past silently. Rule: any page that consumes shared bus data must subscribe its callback on mount (and on mode change), not only on the connect button. Make the subscribe method public + idempotent so multiple call sites are safe.
- [2026-05-18] **Codegen-generated code must compile with strict warnings.** When emitting C/C++ encode/decode functions for messages with only `constant: true` signals, the `src`/`dst`/`data` parameters are unused — GCC's `-Werror=unused-parameter` rejects this. Always add `(void)param;` casts when the loop over non-constant signals is empty. Rust equivalent: emit `let m =` (not `let mut m =`) when no mutation follows; in dispatchers like `decode_frame`, only mark `m` as `mut` when the message is multi-node (mutating `node_id`). Without these guards, generated headers fail compilation in any codebase using `-Werror`.
- [2026-05-18] **C macro names for codegen enums/bitfields must follow ALL_CAPS convention.** First version emitted `motor_controller_v2_switch_mode_mode_POSITION_CONTROL` (lowercased prefix, uppercased only the enum tail). C convention is fully-uppercase macros. Apply `.upper()` to the full prefix before joining with the uppercased value name.
- [2026-05-26] **Svelte 5 snippet params are closures — never spread from them when mutating field-by-field.** Program page's setCustomCanId/Data/Fd helpers spread from the snippet param `stmt.raw` to preserve siblings (`{...stmt.raw, canId: new}`). When the user changed two fields in rapid succession, the second handler's spread used the pre-first-edit value of `stmt`, silently reverting the first change. Fix: read live state from the store inside the helper (locate by id), not from the snippet closure. General rule: snippet `{#snippet name(p)}` params are captured at the moment of `{@render}` and are valid only for that render — never trust them as the source of truth in event handlers that read-modify-write structured data. Use ids to re-query the store.
- [2026-06-06] **Browser-only libraries must NOT be statically imported in a SvelteKit route — SSR (direct page load) crashes with 500.** Bug-183: `/plot` 500'd on direct visit (worked via SPA nav). `import zoomPlugin from 'chartjs-plugin-zoom'` pulls in hammerjs, which reads `window` at module top-level; SvelteKit SSRs every route by default, so Node evaluates the module with no `window` → ReferenceError → 500. SPA nav hid it because the module only loads in the browser then. Fix pattern: lazy-load the offending dep in `onMount` (browser-only) via `const { default: x } = await import('pkg'); Chart.register(x);`, placed before anything that uses it, and drop it from any top-level register/use. Alternative for a fully-interactive page: add `export const ssr = false` in a `+page.ts`. Note `chart.js` core itself is SSR-safe — only chartjs-plugin-zoom (hammerjs) breaks. To debug this class of bug: reproduce with `curl localhost:<port>/<route>` (status 500) and read the `(ssr)` stack in the vite dev log — it names the exact module.

- [2026-08-05] For toc-climb-stairs, use Web GenLib to refresh the pusher payload module only after re-extracting its XML subset from the robot-identical dialect. - [2026-07-30] Expanded the active test from one joint with typed confirmation to prompt-free nodes 1–7 under the existing explicit CLI flag. Individual per-node frames are used for clear acknowledgment/rollback handling; PVT sends are grouped per timing cycle for coordinated motion.
- [2026-07-30] The editable SocketCAN companion treats each `(interface, node_id)` as a distinct joint. Defaults are `can0,can1` and nodes 1–7; raw individual frames were chosen over protocol broadcast so responses, interface failures, and rollback remain attributable per motor.
- [2026-07-31] SocketCAN link configuration remains explicit: `setup` is a standalone operation and `--configure-interfaces` opts into down/configure/up before another command. Normal commands only preflight and never reconfigure a ready shared bus implicitly.
- [2026-07-31] SocketCAN enable sends every selected motor command before waiting, then concurrently collects responses from `can0` and `can1` with a separate 5-second default deadline per target and a CLI/API override. Reverse-disable rollback remains mandatory on any incomplete handshake.
- [2026-07-31] The SocketCAN CLI exposes four distinct lifecycle commands: `enable`/`disable` write register 0x28; `unlock`/`lock` write physical-brake register 0x47. Hold uses the enable/disable lifecycle rather than conflating it with brake control.
