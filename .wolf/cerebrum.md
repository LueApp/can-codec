## Key Learnings

- **A source-only fix to a `.svelte.ts` singleton runes store (e.g. `plotStore`) is NOT live until the runtime reloads it.** Vite HMR does not reliably hot-swap methods on an already-instantiated exported singleton — the running page keeps the old instance/method. After such a fix you MUST fully restart `vite dev` AND hard-reload the browser (Cmd+Shift+R); the deployed Cloudflare site needs `npm run deploy` (build + wrangler pages deploy). Verifying via committed source / a node unit-test alone is insufficient — confirm the *running* app reloaded. (bug-169: the formula phantom-spike fix was correct but the user kept seeing the old behavior because a long-running dev server + un-redeployed site were still executing pre-fix code; proven by reproducing the exported CSV's delta column byte-for-byte with the OLD merge.)
- **Plot formula multi-var merge (`_computeSamples` in plot-store.svelte.ts) must coalesce same-timestamp events.** Signals co-sampled in one frame share an identical timestamp. A per-event sample-and-hold loop that evaluates after each event produces a phantom sample `a(tᵢ) − b(tᵢ₋₁)` (fresh a, stale b) plus a duplicate emit per timestamp. The merge groups all events at the same `time` and evaluates once. Source sample `value` is the **physical** value (`physical_value`), NOT unit-converted — but the chart plots `convertY(series, s.value)`. So formulas operate on stored physical units while the user sees converted units; if a per-signal display-unit pref is active, `a-b` is computed in physical units and may not match the on-screen numbers (latent, separate from the phantom bug). See bug-169.
- **Project:** canfd-codec
- **Description:** A configurable CAN/CAN-FD message encoder/decoder. Define your device's message
- The web codec (codec.ts) `findMessageById` must match the Python codec's DLC-based disambiguation for same-ID multi-node messages. Without it, RegResponse* variants all decode as the first one registered.
- **Same-ID multi-node disambiguation is a 3-stage funnel: ID range → DLC → `constant: true` signals.** `_find_message_by_id` / `findMessageById` take the frame bytes too; after DLC narrowing, any candidate whose `constant: true` signals don't match the actual bits is rejected, then the candidate with the most matched constants wins. This is what lets vesc.yaml's MITControl / PositionControl / SpeedControl / CurrentControl / DutyControl / QueryCommand (all sharing base id 0x000 + node_id, distinguished only by the first-3-bits `mode` constant) decode correctly. If neither DLC nor a constant disambiguates, falls back to first-defined (old behavior). Helpers: `_constant_raw(sig)` / `constantRaw(sig)` compute the expected raw from the signal's `default` (matching encode's enum/bitfield/numeric path); `_match_constants(msg, data)` / `matchConstants(msg, data)` return `(ok, num_matched)`. Both Python and TS implementations must stay in lockstep.
- Chart.js plugin options on custom plugins need a `declare module 'chart.js'` augmentation of `PluginOptionsByType<TType>` to be type-safe. Place the augmentation in a `.d.ts` file (not inside `<script lang="ts">`, where ambient module declarations aren't allowed).
- The plot page renders three chart kinds (signals, timeline, interval) via `renderXxx()` (full rebuild) and `updateLiveXxx()` (incremental). `requestRender(false)` triggers the incremental path; `requestRender(true)` triggers full rebuild. Incremental path works in BOTH paste and live modes (reads from the same stores).
- **chartjs-plugin-zoom mode is static, not per-event:** `zoom.mode` cannot change at runtime based on modifier keys. To get "wheel zooms x by default, Shift+wheel zooms y, Ctrl+wheel zooms xy" you must disable `wheel.enabled` and attach a custom `wheel` listener that calls `chart.zoom({x, y, focalPoint})` with axis factors derived from the event. `chart.zoom({x, y, focalPoint})` works in plugin-zoom 2.x.
- **`chart.resetZoom(transition, mode)` accepts per-axis mode** ('x' | 'y' | 'xy' | 'none') in plugin-zoom 2.x. Use `resetZoom('none', 'x')` for "Fit X without animation" — much cleaner than computing data ranges and writing to scales.
- **Live-update auto-fit must respect user zoom.** Any code path that sets `xScale.min/max` from data every frame will fight the user. Gate the assignment on a `followLive && !userZoomed` flag; flip `userZoomed` true inside plugin-zoom's `onZoomStart` / `onPanStart` callbacks (which expect `boolean | undefined` returns — `void` is a type error, return `undefined` explicitly).
- **chartjs-plugin-zoom SSR fails:** the plugin pulls in `hammerjs` which references `window` at module load. This breaks SvelteKit SSR on the plot route (HTTP 500 on direct page load), but client-side hydration still renders the page correctly. Pre-existing issue, not introduced by zoom UX changes.
- **Plot store has two distinct time scales — keep them straight.** Each sample/entry stores `time` (normalized: `raw_ts - firstTs` in paste mode, `raw_ts - liveStartTime` in live mode) for chart x-positioning, AND `frame.timestamp` (raw wall clock from candump or WebSocket) for display. When constructing Chart.js datum objects, the `absTime` field should carry `frame?.timestamp` (wall clock), not `s.time` — confusing them makes tooltips display 0 even when timestamps were pasted. `plotStore.timelineOrigin` and `timelineMarkers[].time` are also normalized — they get subtracted from chart x, so the timeline click handler must compute normalized time via `pt.x + plotStore.timelineOrigin`, not via `pt.absTime`.
- **`parseCandump` must extract the timestamp BEFORE running the body regex.** Real-world candump variants insert direction/flag tokens between the interface and the CAN ID — e.g., `(ts) can0 TX B - 00010101 [35] DATA`. A single regex with `(?:\((\d+\.\d+)\)\s+)?(\S+)\s+([0-9A-Fa-f]+)\s+\[...` will silently drop the timestamp on these lines because JS `match()` backtracks past the optional ts group when the rest can't align in one pass — the parse "succeeds" with `timestamp: undefined`, and downstream all chart x-positions collapse to 0 (especially nasty for MAVLink-over-CAN where ts gets coerced to 0 into the reassembler). Fix: peel off the leading `(NUMBER.NUMBER)` first, then run body parsers on the remainder. Also keep a `(?:\S+\s+){0,4}` slot in the candump body regex to absorb direction/flag tokens between iface and ID.
- **`updateLiveSignalCharts` must use `plotStore.getSamples(key)`, not `liveSampleStore.get(key)`.** Paste-mode samples live in `allSeries[].samples`, not `liveSampleStore`. The `updateLive*` functions run on any `requestRender(false)` — including paste-mode actions like setting t=0 or toggling apply-to-all — so reading from the wrong store blanks the chart in paste mode. The `follow` window logic must be gated by `plotStore.mode === 'live'` for the same reason: `followLive` defaults to true and would otherwise clamp paste-mode x ranges.
- **MAVLink XML `<extensions/>` marker:** Per the MAVLink2 spec, fields after `<extensions/>` are appended to the wire payload in *declaration order* (NOT sorted by size) and are *excluded from CRC_EXTRA*. Only core fields (before the marker) are size-sorted and contribute to CRC_EXTRA. This must be done by walking the message's child elements in order — `querySelectorAll('field')` / `findall('field')` won't tell you which side of the marker each field is on. Implemented in `canfd_codec/mavlink_loader.py` `_parse_messages` and `web/src/lib/config-loader.ts` `parseMavlinkXml`.
- **MAVLink-over-CAN multi-frame reassembly:** Continuation CAN frames carry no identifier (only the first frame has 0xFD). Total wire length is `12 + payload_len` (byte 1 of the 0xFD header). `MavlinkReassembler` (both Python and TS) keys buffers by CAN ID with FIFO concurrent buffers, decoding when `currentLength >= expectedTotal`. This handles realistic interleaving at *different* CAN IDs cleanly; at the *same* CAN ID with same-size messages, FIFO can mis-assign continuation frames — limitation by design since continuation frames have no ID. The reassembler is used by `canfd_codec/monitor.py`, `cli.py cmd_decode` (multi-data args), and `web/src/lib/plot-store.svelte.ts` analyze+handleLiveFrame.
- **MAVLink decode in Codec class needs `decode_mavlink`, not `decode`:** `Codec._find_message_by_id` only checks `_by_id`; MAVLink messages live in `_by_mavlink_id`. Use `Codec.decode_mavlink(msg_id, payload, actual_can_id=...)` after parsing the v2 header.
- **MAVLink CAN-transport 29-bit ID is now a DESTINATION-BASED layout (synced 2026-06-05 to mavlink_bridge):** `bit 28` = header; `bits 27:20` sender_sys (8b); `bits 19:14` sender_comp (6b, ≤63); `bits 13:6` target_sys (8b); `bits 5:0` target_comp (6b, ≤63). `make_id = (1<<28)|(ss<<20)|((sc&0x3F)<<14)|(ts<<6)|(tc&0x3F)`; detection is `id & 0x10000000` (bit 28), NOT the old `id & 0x10000` (bit 16). Broadcast = target 0.0. The OLD format (bit-16 marker, `sys<<8|comp`) is fully replaced — old IDs like 0x10101 are now correctly NOT detected as MAVLink. Source of truth: `mavlink_loader.py` helpers (`mavlink_can_make_id`, `mavlink_can_is_mavlink`, `mavlink_can_id_sender_sys/sender_comp/target_sys/target_comp`); mirrored in `web/src/lib/codec.ts` (`mavlinkCanMakeId`, `isMavlinkCanId`, `mavlinkCanSenderSys`/etc.). All detection sites must use bit 28: `cli.py` decode, `monitor.py` (×2), `codec.ts` smartDecode, `plot-store.svelte.ts` isMavlinkCanId, `decode/+page.svelte` isMavlinkCanId. `MavlinkInfo` (types.ts) carries sender_sys/sender_comp/target_sys/target_comp (no more sys_id/comp_id). On encode, `--sys-id/--comp-id` = local sender; target is derived from the message's `target_system`/`target_component` field values (or `--target-sys`/`--target-comp`), else broadcast — mirrored in web `encodeMavlink`.

- **Open-loop SOP runner = `sequence-store.svelte.ts`.** Replaced flat steps[] with a recursive AST (statement types: `send`, `wait`, `repeat`, `every`, `sweep`, `group`). Cancellation: `running` flag + tracked timer/interval handles → `stop()` is immediate. JSON import/export uses `{version:2, ast}` wrapper and re-IDs everything on import.
- **`every` statement semantics — TWO modes triggered by `durationMs`.** When `durationMs` is unset, `every` is *background*: parent body advances immediately, the periodic task keeps firing until the *enclosing body* ends (the `_runBody` finally clears intervals it tracked) or `stop()` is called. When `durationMs` is set, `every` is *blocking*: parent waits for the duration, then the interval is cleared. Tests rely on this: heartbeat + commands needs background; "burst for N ms then continue" needs bounded. Each `_runBody` invocation tracks its own `localIntervals` so background `every`s scoped inside `repeat`/`group` get cleaned up at scope end — don't leak intervals up to the top scope.
- **Discriminated-union AST mutation pattern.** `SeqStatement` is a union; methods like `addStmt(parent, stmt: Omit<SeqStatement,'id'>)` cause TypeScript to lose per-variant property access (e.g. `raw` on `SendStmt`, `body` on `RepeatStmt`). Fix: make the method generic: `addStmt<T extends SeqStatement>(parent, stmt: Omit<T,'id'> & {id?: string})`. Callers can pass plain literals when T can be inferred, or write `addStmt<SendStmt>(null, {...})` for explicit narrowing. Inside the method, cast as `unknown as SeqStatement` (not just `as SeqStatement`) — when the union has variants with required fields not present on the generic (e.g. `SetStmt.name`, `SetStmt.expr`), TS rejects the single-step cast. The mutateAst() helper uses `JSON.parse(JSON.stringify(ast))` for deep clone — fine for AST values which are POJO-shaped (no functions/Dates), and forces full Svelte 5 reactivity by reassigning the top-level array.
- **Sequence variables = `set` statement + `=expr` syntax + tiny arithmetic evaluator.** `SetStmt { type:'set', name, expr }` writes to a per-run `vars: Record<string, number>` map (cleared on `start()`). Any send value of the form `"=expr"` is resolved against `vars` at send time. The evaluator is a hand-written recursive-descent parser supporting `+ - * / %`, parentheses, unary `+/-`, decimal and hex literals (`0x10`), and bare identifier lookups. NOT `eval()` and NOT Turing-complete — just arithmetic. Throws on undefined variable, malformed input, or trailing tokens. For the preview path (`encodeSendPreview`), the store walks the AST in document order up to the target send and replays any `set` statements it encounters — best-effort: skips disabled, ignores per-iteration updates in repeat/every (one pass through bodies). Variables only resolve numerically; for fields that take other shapes (bitfield bitmaps, enum-name strings), the user keeps writing literal values as before.
- **HTML5 drag-and-drop on tree rows.** Five rules that prevent the common pitfalls: (1) put `draggable=true` on the row itself for "click-anywhere to drag" UX, then in `dragstart` call `e.preventDefault()` if `e.target.closest('input, select, textarea, button, label, .ast-actions, .send-editor')` — this keeps form controls / nested editors interactive while making the row body grab-able. (2) **CRITICAL when rows nest:** call `e.stopPropagation()` in `dragstart` and `dragend`. Without it, the inner row's `dragstart` bubbles to the parent's draggable row, which fires its own handler and overwrites `dragId` to the parent's id — so dragging a child out of an `every`/`repeat`/`group` silently moves the *container* instead of the child. (3) In `dragover`, MUST call `e.preventDefault()` to signal "drop allowed here" — otherwise `drop` won't fire — and `e.stopPropagation()` so only the innermost row resolves the drop target. (4) **Anchor before/after/inside drop zones to the row's HEADER element (`.ast-line`), NOT the whole `.ast-row` bounding rect.** When a container has children, its row can be hundreds of pixels tall, and using the full rect makes the middle 40 % "inside" zone swallow the entire body — leaving no usable drop area for children-of-the-container to be dragged *out*. With the header as anchor: cursor above bottom of header is before/after based on top/bottom half; cursor below the header is 'inside' (for containers) or 'after' (for leaves). (5) Cycle check direction matters: refuse drops where the *target* lives inside the *dragged subtree* — i.e., walk dragId's body looking for stmt.id, not the other way around. The opposite direction (walking stmt.body for dragId) is "already inside" check, which is a different concern (and dropping inside a container you're already in is a valid reorder-to-last move, not a refusal case). Don't try to use `dragleave` to clear the drop indicator — it fires unpredictably when moving between child rows. Just let the next `dragover` overwrite it, and clear on `dragend`.
- **Drag-and-drop cycle prevention.** When the user drags a container into one of its own descendants, the move must be refused — otherwise the tree becomes a cycle and recursive traversal hangs. Implement as `_isDescendantOf(maybeChild, maybeAncestor)` walking the ancestor's body subtree. Cheap because the AST is small. Sequence-store's `moveStmtTo` does this check before mutating; the UI also short-circuits `dragover` (no `e.preventDefault()`) so the cursor shows a "no drop" icon and the drop indicator never appears.
- **`SERVER_SCRIPT` is the single source of truth in `web/src/lib/server-script.ts`.** Both `/plot` and `/encode` import `downloadServerScript()` from there. - **`canfd-codec genlib` is the device-library generator. The four per-language emitters (`canfd_codec/codegen/python_gen.py`, `c_gen.py`, `cpp_gen.py`, `rust_gen.py`) each re-implement the same bit-pack/extract + scale/offset + signed/float-reinterpret algorithm as `codec.py`.** They MUST stay bit-exact with the master codec — verified via roundtrip on `example_damiao.yaml` and `motorv2.yaml` (encoded MITControl `8f5b7ff0510517ff` across all 4 languages). - **The web UI mirrors the CLI codegen at `web/src/lib/codegen/{python,c,cpp,rust}.ts` + `common.ts` + `index.ts`, exposed via `/genlib` route (`web/src/routes/genlib/+page.svelte`).** Output is *runtime* bit-identical to the CLI but not byte-identical text: JS Number can't distinguish int 0 from float 0.0 (web emits `0.0`, Python CLI emits `0` for YAML int values), and JS `.toString()` uses shortest-round-trip while Python `repr` uses scientific notation for small floats (`9.587e-05` vs `0.00009587...`). - **Embedding literal `{` / `}` in Svelte templates (e.g. udev rule snippets inside `<pre><code>`):** Use the HTML5 named entities `&lcub;` (for `{`) and `&rcub;` (for `}`). Verified end-to-end on `web/src/routes/docs/+page.svelte` USB permissions section — `ATTR&lcub;idVendor&rcub;` renders as `ATTR{idVendor}` in the DOM, no compile warnings. - **ZLG USBCAN/USBCANFD CSV export format** (e.g. `can_*.csv` from ZLG tooling). 21-column header starting `WRITE_TIME,GROUP_ID,DEVICE_TYPE,...,MAKE_CAN_ID(HEX),FORMAT,FRAME_TYPE,DLC,__PAD,__RES0,__RES1,DATA(HEX)`. Critical columns: `MAKE_CAN_ID(HEX)` (column name, e.g. `0x10101` — strip `0x`), `CAN/CANFD` (`can_fd`|`can`), `RX_TIMESTAMP` (`[<microseconds>]` — bracketed integer µs, divide by 1e6 for seconds; SYS_MS shows wall-clock HH:MM:SS.mmm and is *not* monotonic per-frame), `DATA(HEX)` (space-separated bytes, trailing space possible). `WRITE_TIME` is file-write time, NOT message arrival time — don't use for plot x-axis. `zlgCsvToCandump()` in `web/src/lib/plot-store.svelte.ts` emits cansend-format `(secs) can0 ID##1HEX` (FD) or `(secs) can0 ID#HEX` (classic) so existing `parseCandump` consumes it without a separate parse path. - **Per-signal unit display preference system.** Module `web/src/lib/unit-conversion.ts` defines 5 unit families (angular_velocity rad/s↔rpm↔deg/s↔rev/s, angle rad↔deg↔rev, temperature K↔°C↔°F with affine fns, linear_velocity m/s↔km/h↔mph↔cm/s↔mm/s, linear_distance m↔mm↔cm↔km↔in↔ft). Aliases handle YAML variants (e.g. "C"→"°C", "rps"→"rev/s"). `UNIT_INDEX` lookup is case-insensitive. Preference store `web/src/lib/unit-pref-store.svelte.ts` keys by `messageName::signalName` and persists to `cancodec_unit_prefs_v1`. Picker UI is a `<select class="unit-select">` inserted into the signals table on `web/src/routes/+page.svelte` — only renders when `getCompatibleUnits(sig.unit).length > 1`. Decode/plot/encode pages each resolve via `unitPrefs.resolve(msgName, sigName, rawUnit)`. `displayValue` in `codec.ts` was extended with an optional `{value?, unit?}` override so callers can format the converted value through the same code path. **Encode flow:** user enters value in display unit → `nativeNumber()` converts back to YAML-native unit → passed to `codec.encode()`. Defaults shown in the placeholder are also converted to the display unit via `displayDefault()`. **Plot reactivity:** a top-level `$effect` reads `unitPrefs.prefs` and calls `renderCharts()` when prefs change, so charts auto-redraw on dropdown change. **Critical: plot's `series.group` is a *decorated* label** (e.g. `"Feedback / N1"` for multi-node, `"1.1 / FOO"` for MAVLink, or with trailing mux suffix `" [mode=...]"`) — the lookup must first strip these via `baseMessageName(group)` before calling `unitPrefs.resolve`, otherwise the pref keyed on plain `"Feedback"` won't match.
- **Headless Chrome E2E for SvelteKit web app.** CDP at `http://127.0.0.1:9222`. `Page.navigate` is a hard nav but the codecStore singleton might still see stale state on the first post-nav render — use `location.href = '...'` instead for guaranteed module re-init, or trigger SPA nav by clicking an `<a href="/route">` link. For SvelteKit SSR routes that fail server-side (e.g. `/plot` 500s from `hammerjs`'s `window` ref), SPA-nav into them from `/` works fine — the client bundle renders identically. Always force EN locale (`localStorage.setItem('can-codec-locale','en')`) before matching button text since headless Chrome defaults can pull `zh` from `navigator.languages`. **Two CDP gotchas:** (1) `localStorage` access fails on `about:blank` — navigate to the target origin first, then set/get. (2) Each `Runtime.evaluate` shares the same global scope, so `const x = ...` in one eval shadows the next call's redeclaration. Wrap each eval's body in `{ ... }` to give it its own block scope.
- **Plot page "Formulas" feature (derived signals)** lives in `plot-store.svelte.ts` + `plot/+page.svelte`. Model: `DerivedSignal { id, name, expr, unit, vars: Record<varName, sourceKey>, perNode?: boolean }` in `plot-types.ts`. The store maintains derived entries as virtual `SignalSeries` in `allSeries` with `group === DERIVED_GROUP` ("Formulas") and `samples: []` — the real samples are computed on demand by `getSamples()` → `_resolveSamples()` → `_computeSamples()`. Reuses `evalExpr` from `sequence-store.svelte.ts` (no eval/Function, just a tiny + − * / % parser with hex literals). Single-var formulas map sample-for-sample; multi-var uses sorted event list with sample-and-hold (skips events until all vars have ever been seen). **Chained formulas:** a var's source can be another formula's key — `_resolveSamples` dispatches to source vs derived, carrying a `visiting` set of derived ids/instances for cycle protection at runtime. `_wouldCycle` provides save-time validation by walking the dependency tree. **Per-node templates:** when `perNode: true`, var values use the placeholder `N*` (e.g. `"MotorFeedback / N* / target"`). `_derivedAsSeries` expands the formula into one virtual SignalSeries per node where every templated binding resolves (intersection of nodes via `_discoverNodesForFormula` + `_matchTemplate`). Series keys look like `"Formulas / delta_N1"`. At sample-resolve time, `_matchPerNodeKey` parses the trailing `_N<n>` and substitutes `N*` → `N<n>` in each templated var; static (non-N*) bindings pass through unchanged. Persisted in `localStorage` under `cancodec_derived_signals_v1` and in layout YAML under `plot.formulas`. `resetData()` preserves derived-only chartPanels so formulas survive analyze() / clearData(). Name validation: regex `^[A-Za-z_][A-Za-z0-9_]*$` to keep names usable as identifiers. UI: a `perNode` checkbox; the var-binding `<select>` collapses multi-node sources into "N*" options (with node-count badge) when the checkbox is on.
- **Custom raw-frame send via SendStmt.raw.** The Program page (`web/src/routes/program/+page.svelte`) lets users send a CAN frame without a loaded config by picking `-- custom (raw frame) --` (sentinel `__custom__`) at the top of the message dropdown. `pickMessage()` translates the sentinel into `{ msgName: '', isMavlink: false, isBroadcast: false, raw: stmt.raw ?? {canId:0, data:[], isFd:false} }`. The editor body switches on `isCustomSend(stmt) = !stmt.msgName && !!stmt.raw` to render CAN ID hex / data bytes hex / CAN FD checkbox instead of the signal grid. Encoding goes through the pre-existing `_encodeSend` raw fallback (sequence-store) — no new statement type, no new runtime path. **Critical:** the field-wise setters MUST re-read raw from the store via `liveRaw(stmt.id)` (locate by id in `sequenceStore.ast`), NOT spread from the snippet's closure-captured `stmt.raw` — see Do-Not-Repeat entry on stale snippet params. Switching the picker BACK to a real message clears `raw: undefined` so JSON.stringify drops the key.

## Do-Not-Repeat

- [2026-05-06] When renaming a field in a persisted type (e.g. localStorage), always add migration/normalization logic that handles old stored data. An entry may exist with the old field name, causing undefined access on the new name. Use a normalizer that ensures all required fields exist.
- [2026-05-06] In Svelte 5, never mutate `$state` objects inside template expressions or `$derived`. Methods called from templates (like `getMessageFilter`) must be pure reads — return new objects with safe defaults instead of mutating the source. Mutations are only safe in event handlers (onclick etc.).
- [2026-05-16] **When sharing a connection across pages (busStore), connection state and per-consumer subscriptions are separate concerns — don't conflate them.** Bug-057: plot only subscribed its frame callback inside `connectLive()` (the Connect button handler). When /encode connected the bus first, plot's Connect button was hidden and the callback never subscribed — frames flowed past silently. Rule: any page that consumes shared bus data must subscribe its callback on mount (and on mode change), not only on the connect button. Make the subscribe method public + idempotent so multiple call sites are safe.
- [2026-05-18] **Codegen-generated code must compile with strict warnings.** When emitting C/C++ encode/decode functions for messages with only `constant: true` signals, the `src`/`dst`/`data` parameters are unused — GCC's `-Werror=unused-parameter` rejects this. Always add `(void)param;` casts when the loop over non-constant signals is empty. Rust equivalent: emit `let m =` (not `let mut m =`) when no mutation follows; in dispatchers like `decode_frame`, only mark `m` as `mut` when the message is multi-node (mutating `node_id`). Without these guards, generated headers fail compilation in any codebase using `-Werror`.
- [2026-05-18] **C macro names for codegen enums/bitfields must follow ALL_CAPS convention.** First version emitted `motor_controller_v2_switch_mode_mode_POSITION_CONTROL` (lowercased prefix, uppercased only the enum tail). C convention is fully-uppercase macros. Apply `.upper()` to the full prefix before joining with the uppercased value name.
- [2026-05-26] **Svelte 5 snippet params are closures — never spread from them when mutating field-by-field.** Program page's setCustomCanId/Data/Fd helpers spread from the snippet param `stmt.raw` to preserve siblings (`{...stmt.raw, canId: new}`). When the user changed two fields in rapid succession, the second handler's spread used the pre-first-edit value of `stmt`, silently reverting the first change. Fix: read live state from the store inside the helper (locate by id), not from the snippet closure. General rule: snippet `{#snippet name(p)}` params are captured at the moment of `{@render}` and are valid only for that render — never trust them as the source of truth in event handlers that read-modify-write structured data. Use ids to re-query the store.
- [2026-06-06] **Browser-only libraries must NOT be statically imported in a SvelteKit route — SSR (direct page load) crashes with 500.** Bug-183: `/plot` 500'd on direct visit (worked via SPA nav). `import zoomPlugin from 'chartjs-plugin-zoom'` pulls in hammerjs, which reads `window` at module top-level; SvelteKit SSRs every route by default, so Node evaluates the module with no `window` → ReferenceError → 500. SPA nav hid it because the module only loads in the browser then. Fix pattern: lazy-load the offending dep in `onMount` (browser-only) via `const { default: x } = await import('pkg'); Chart.register(x);`, placed before anything that uses it, and drop it from any top-level register/use. Alternative for a fully-interactive page: add `export const ssr = false` in a `+page.ts`. Note `chart.js` core itself is SSR-safe — only chartjs-plugin-zoom (hammerjs) breaks. To debug this class of bug: reproduce with `curl localhost:<port>/<route>` (status 500) and read the `(ssr)` stack in the vite dev log — it names the exact module.
